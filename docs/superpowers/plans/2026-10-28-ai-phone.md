# AI Phone Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** When Retell's AI answers a missed shop call, the call lands in the admin. A real inquiry becomes a lead, Carlos gets an email alert, and every call shows on a Calls page.

**Architecture:** Retell posts `call_analyzed` to a signed webhook at `/api/phone/retell`. A pure parser turns the payload into a `CallInput`. `saveCall` applies the design's rules (new lead, add to an open lead, or no lead) in Postgres. The route then emails the alert through the existing Resend setup, using the same "save first, always email, 500 only if nothing was kept" fallback as `/api/quote`. The AI's instructions are generated from the website's own data and shown on an owner-only setup page, where they can be copied into Retell.

**Tech Stack:** Next.js 14 app router, TypeScript, Postgres (Neon live, PGlite in tests), Resend, vitest, Tailwind.

**Spec:** `docs/superpowers/specs/2026-10-28-ai-phone-design.md`

## Global Constraints

- **Dependencies:** no new runtime dependency. Signature checking uses `node:crypto`. `retell-sdk` may be added only as a pinned devDependency, for the cross-check test in Task 2.
- **Secrets:** `RETELL_API_KEY` is read only from `process.env`. It is never logged, printed, committed or written into docs.
- **Database:** records are never deleted.
- **Time:** times are shown in Eastern time (`America/New_York`).
- **Security:**
  - Every page under `/admin` calls `requireUser()`. The setup page calls `requireUser("owner")`.
  - Caller-supplied text is escaped in email HTML, and it is never put into a URL or `href` except as a `tel:` digits-only link.
- **Copy:** the AI's instructions follow Carlos's warm, needs-first texting style. The "Must never happen" rules are written into them word for word.
- **Email alert subject:** `Missed call — {name} — {first service or "Not sure yet"}`, with `Urgent: ` in front when urgent. The Resend idempotency key is `call-alert-{retell_call_id}`.
- **Before every commit:** `npm test` passes. Tasks that touch pages also pass `npm run build`.
- **Commit settings:**
  - Identity: `git -c user.name=xophsy -c user.email=111628173+xophsy@users.noreply.github.com commit ...`
  - Every message ends with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
  - Pushing to `main` is pre-approved by the owner.

## Review Focus

1. **Forwarding can replace the caller ID with the shop's own number, (919) 526-0818.** That would turn every call into one customer. The shop's own number must count as no caller ID. Tested in Task 2.
2. **The AI may fill an empty field with placeholder words** such as "unknown", "N/A", "not provided" or "none". These must count as missing, so no customer is ever named "N/A". Tested in Task 2.
3. **Our signature check must accept Retell's real signatures.** If our reading of the format is wrong, every real call gets a 401. The SDK cross-check is in Task 2.
4. **Hostile or odd caller text:**
   - HTML in the summary or name is escaped in the email (Task 3).
   - A `recording_url` that isn't `https:` is dropped (Task 2).
   - Long text is cut to its limit (Task 2).
5. **A retry after a partial failure** (the call saved, the email failed) must email once and create no second lead. Covered in Task 1 (duplicate) and Task 3 (duplicate still emails, with the same key).

`leads.ts` also exports `UNKNOWN_CALLER = "Unknown caller"`.

**Table and rules:**

- **`calls` columns:** the spec's columns plus `caller_name text`. The spec's list leaves it out, but a call with no number still needs a name to show.
  - `retell_call_id text not null unique`
  - `call_type` has a check constraint over `CALL_TYPES`
  - `customer_id` and `lead_id` are nullable FKs
  - Indexes: `(created_at desc)` and `(lead_id)`
- **Open lead:**
  - `stage in ('new','contacted','quoted')`, `archived_at is null`, and `updated_at > now() - interval '30 days'`; take the newest.
  - Ruling: this uses `updated_at` rather than `created_at`, so a quote that is still being worked on but was started more than 30 days ago still counts.
- **Order inside `saveCall`:**
  1. In `DEMO`, throw, matching `saveWebsiteLead`.
  2. If a row with this `retell_call_id` exists, return it with `duplicate: true` and the outcome it first had:
     - no lead → `"no-lead"`
     - this is the lead's earliest call → `"new-lead"`
     - otherwise → `"added-to-lead"`

     That way a retried alert gets the same subject as the first one.
  3. Customer, vehicle and lead work.
  4. Insert the call last, `on conflict (retell_call_id) do nothing`. A retry after a failure part-way through then reuses the customer and the open lead instead of making new ones.
- **Rules by call type:**

| Case | Customer | Lead | Activity |
|---|---|---|---|
| `spam`, or `!callerSpoke` | none | none | none |
| no `callbackPhone` | none | none | none |
| `inquiry` | upsert (`callerName ?? UNKNOWN_CALLER`) | open lead → touch `updated_at`, else create one (source `phone`, `services = serviceKeys`, vehicle row if given, message below) | `logActivity("lead", leadId, "created" \| "call", null)` |
| `existing_customer` | upsert | add to the open lead if there is one, never create one | `logActivity("lead", leadId, "call", null)` if added |
| `vendor` / `other` with a number | none | none | none |

- **New lead message:** the summary. When there is a timeframe, add a new line with `When: {timeframe}`.
- **Name filling:**
  - Change `upsertCustomer` so that on conflict, `name` is replaced only when the stored name is `UNKNOWN_CALLER`.
  - Website leads get the same fix for free.

```ts
// lib/phone/retell.ts
export function verifyRetellSignature(rawBody: string, apiKey: string, header: string | null, now?: number): boolean;
export function parseRetellCall(call: unknown): CallInput | null;  // null when call_id is missing
```

**Signature algorithm.** Matches `retell-sdk`'s webhook check; the cross-check test proves it.
- The header must match `/^v=(\d+),d=([0-9a-f]{64})$/i`.
- `|now - Number(v)|` must be at most `300_000` ms.
- Compute the HMAC-SHA256 with `apiKey` as the key, over `rawBody + v` (the original digits).
- Compare with `timingSafeEqual` against the hex digest.
- A missing header or one that doesn't match the pattern → `false`.

**Parsing rules:**

- **Where the fields come from:**
  - From the call object: `call_id`, `from_number`, `transcript`, `transcript_object`, `recording_url`, `start_timestamp` and `end_timestamp` (both in ms).
  - From `call_analysis`: `call_summary` and `custom_analysis_data`.
- **Custom fields:** `caller_name`, `callback_number`, `vehicle`, `service_keys` (comma-separated), `timeframe`, `call_type` and `urgent`.
- **Strings:** trimmed and cut to these lengths: name 100, vehicle 120, timeframe 120, summary 2000, transcript 50,000, `from_number` 40.
  - Placeholders become null, matched case-insensitively and ignoring trailing punctuation: `""`, `unknown`, `n/a`, `na`, `none`, `not provided`, `not given`, `null`.
- **`callbackPhone`:**
  - Use `normalizePhone(callback_number)`, falling back to `normalizePhone(from_number)`.
  - Drop the result if it equals the shop's own number, `19195260818`.
  - Then `formatPhone` it.
- **`serviceKeys`:** split on commas, trim, keep only keys where `serviceName(k)` isn't null, remove duplicates, at most 10.
- **`callType`:** the value if it's in `CALL_TYPES`, otherwise `"other"`. **`urgent`:** `=== true`.
- **`recordingUrl`:** kept only if it parses as a URL with protocol `https:`.
- **`callerSpoke`:**
  - If `transcript_object` is an array: true when some entry has `role === "user"` and non-blank content.
  - Otherwise: `/^User:\s*\S/m.test(transcript)`.
- **Timestamps:** a finite number becomes a `Date`, anything else becomes null.

**Alert content:**

- **Subject:** `{Urgent: }Missed call — {who} — {what}`.
  - `who`: `callerName ?? callbackPhone ?? "No caller ID"`, plus ` called again` when `saved?.outcome === "added-to-lead"`.
  - `what`: depends on the call type.
    - `inquiry`: the first service's name, or `Not sure yet`.
    - `existing_customer`: `existing customer`.
    - `vendor` or `other`: `not a lead`.
- **Body:**
  - The summary, vehicle, timeframe and urgency, as rows in the quote email's table style.
  - The callback number as a `tel:` link built only from its digits.
  - `{siteUrl}/admin/leads/{leadId}` when there is a lead.
  - The plain `text` version carries the same rows.

**Route flow:**
1. `RETELL_API_KEY` missing → log, return 500.
2. Bad signature → 401. Bad JSON → 400.
3. `event !== "call_analyzed"` → 204.
4. `parseRetellCall` returns null → 400.
5. `saved = await saveCall(call)`, catching and logging failures (`saved = null`).
6. If `shouldAlert(call)` and `RESEND_API_KEY` is set: send with the idempotency key `call-alert-${call.retellCallId}`, using `siteUrl = new URL(request.url).origin`.
7. Return 204 when `saved` is set, or when the email went out, or when `!shouldAlert(call)`. Otherwise return 500, so Retell retries.
